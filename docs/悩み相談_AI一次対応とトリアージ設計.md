# 悩み相談 AI一次対応・トリアージ設計

最終更新: 2026-05-26
対象機能: CoHub ひろば「悩み相談」(plaza category=`相談` / 現行UI名 🆘 悩み相談)
ステータス: 基本方針・トリアージ・つなぐ先=**確定** / ワークフロー詳細=**設計中**

---

## 1. 背景・目的

ひろばの「悩み相談」に投稿された内容に対し、AIをどう起用するかを設計する。
相談ボードが死ぬ最大要因は **「投稿したのに誰も反応しない（沈黙）」**。
一方、健康・メンタル相談には **誤回答リスク** と **責任問題** があり、
推進メンバーは医療の専門家ではない。
この2つを両立させる設計を行う。

## 2. 基本方針

### 2.1 黒子型（AIは前に出ない）
- **AIが単独で公開の一次回答をすることはしない。**
- AIは「①沈黙を防ぐ安全網」と「②人の回答を助ける下書き役」に徹する。
- 表（投稿者が見る画面）に出る回答は、原則 **人が自分の言葉で** 行う。
- 理由:
  - メンタル/深刻案件をAIが軽く扱うと有害＋責任問題。
  - AIが即答すると人の反応が止まり、CoWellが本来狙う **つながり・社会的伝染** が薄れる。

### 2.2 推進メンバーの役割を再定義
推進メンバーは専門知識を持たない。よって役割を
**「答える人」→「受け止めて、適切な人につなぐ人（ハブ）」** と定義する。
彼らの価値は運管型＝現場との近さによる **気づく・受け止める・つなぐ・見守る**。

## 3. 3段階トリアージ（確定）

| Tier | 想定例 | 対応者・つなぐ先 | AIの下書き |
|---|---|---|---|
| **Tier 1** 軽い・一般 | 寒暖差頭痛、肩こり、軽い食事相談 | 推進メンバーがピア対応し本人へ返信 | 共感＋一般Tips＋次の一歩（医療判断はしない） |
| **Tier 2** 要観察・健康相談 | 継続する不調、睡眠、血圧、強いストレス | **→ 安島なつき（NPO法人ヘルスケアネットワーク）** | 「専門におつなぎします」文面＋論点。診断・断定はしない |
| **Tier 3** メンタル危機 | 希死念慮、ハラスメント、メンタル危機 | NPOは対応困難 → **西村さんに連絡 → 西村さんが産業医を紹介** → 産業医/医療機関＋管理者、本人の安全最優先 | AIは助言を出さず、エスカレーション手順のみ |

- Tier 判定は **AIが投稿内容から一次推定（＋深刻ワード検知）**、**推進メンバーが手動で上げ下げ**できる。迷ったら上のTierへ倒す（安全側）。
- 「囲んで意見を交わす」協議モーダルを作る場合、**対象は Tier 1 のみ**（Tier 2・3 は協議より速やかに正しい窓口へ流すのが正解）。

## 4. 役割・つなぐ先（確定）

- **推進メンバー（g_field_voice グループ／is_field_promoter）**: Tier 1 のピア対応と、Tier 2・3 の振り分け（受け止めてつなぐ）。
- **安島なつき（dalerisu）= NPO法人ヘルスケアネットワーク**: 健康相談の専門窓口（Tier 2）。`is_guest_reviewer=1`、g_field_voice 所属済み。メンタルレベルの危機対応は範囲外。
- **西村幸子（s_nishimura）= 観察者（研究者）**: 本PJを論文化するため当事者として回答しない。g_field_voice には残すが **傍観者**。能動回答や主担当には割り当てない。**例外: Tier 3 危機時のみ「産業医を紹介する窓口」として動く**（介入ではなく安全のための紹介なので研究中立性は保たれる）。
- **産業医**: 常設指定なし。危機時に西村さん経由で都度紹介。
- **外部相談窓口（SMTPメール転送、index.js に実装あり）**: 現在 SMTP 未設定で無効。西村→産業医ルートでカバーできるため当面は有効化不要。
- **福田吉治教授・帝京大学大学院（is_guest_reviewer）**: 施策の「監修」役。個別の悩み相談には充てない。

## 5. 既存実装（2026-05-26 時点で稼働中）

`server/routes/plaza.js` `notifyConsultToPromoters()`:
- 相談カテゴリ投稿時、AI(`generateText`)が回答下書き（共感＋一般助言＋次の一歩＋回答者向けメモ）を生成。
- 推進グループ **g_field_voice**（room_code=`grp_g_field_voice`）へ **bot_health（ヘルスアドバイザー）名義** で投稿＋`emitToGroupMembers`＋push通知。
- **深刻ワード正規表現**（死にたい/消えたい/自殺/辞めたい/パワハラ/セクハラ/うつ/いじめ 等）検知時は AI 助言を出さず 🚨 緊急エスカレーション文面に切替（保健師・管理者・外部窓口、安全確認最優先、push `requireInteraction`）。
- 非同期 fire-and-forget で投稿成立を妨げない。匿名投稿はニックネーム(🎭)で通知し匿名性維持。

→ この「深刻ワード検知→AI助言停止→エスカレ」が **Tier 3 の土台** に相当（既にある）。

## 6. 安全・倫理の原則

- AIにも人にも **診断・医療判断・断定をさせない**（一般情報と「専門へ」の導線まで）。
- **匿名性の維持**: 投稿は匿名（ニックネーム）。協議や通知でも実名を出さない。
- **表裏分離**: 裏（推進メンバーの協議）の生々しさは本人に見せず、表は1つの整った温かい返事に収束させる。「管理側に囲まれて議論されている」感（監視・晒し）を本人に与えない。
- **研究中立性**: 観察者（西村）を当事者ループに入れない。
- **過剰投資しない**: 「囲む」円形UI等の見た目は、ワークフローが回ることを検証してから投資する。

## 7. 未実装・今後の設計論点

1. **Tier 自動判定**: AI推定のしきい値設計＋推進メンバーの手動上げ下げUI。
2. **主担当の決め方**: Tier 1 を誰が締めるか（営業所別／カテゴリ別／輪番／立候補）。※西村さんは割り当て対象外。
3. **本人への見せ方（Tier別の体験）**: Tier 1=温かい返事／Tier 2=「専門におつなぎします」／Tier 3=「すぐ連絡します」。
4. **協議モーダル**: 「悩みを中心に推進メンバーが非同期で視点を寄せ、AIが1つに統合、主担当が締める」ビューを作るか、まずテキストスレッドで十分か。
   - 時間差があるためリアルタイム議論は狙わない。**非同期で視点が集まり→収束→1つの返事**にする。
